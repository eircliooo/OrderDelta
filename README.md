# 外贸订单差异雷达（MVP-0）

**把报价单、客户 PO、形式发票的 Excel 放在一起，逐项列出它们对不上的地方，并指出每条差异来自哪个文件的哪个单元格。**

这是一个**辅助核对**工具。它不替你做决定，也不替你承担责任——最终判断永远是你的。

## 1. 它解决什么问题

外贸业务员每天都在做同一件苦力活：

> 报价单发出去了 → 客户回了一份 PO → 我方开一张 PI 给客户确认。
> 这三份文件必须一致。可它们由三个人、在三个时间、用三套 Excel 模板做出来。

于是常年发生这些事：

- 客户 PO 上的数量是 1200，PI 上还是报价时的 1000 —— 发货短了 200 个
- 单价从 2.40 改成 2.50，行金额忘了跟着改 —— 收款金额和合同对不上
- 贸易术语从 FOB 变成 CIF —— 一整段海运费不知道谁出
- 报价单上有三个型号，PI 上只剩两个 —— 漏了一个型号没做
- 币种一边写 USD 一边写 `$` —— 到底是美元还是港币

人工核对不是不能做，是**又慢又不稳定**：三份文件 30 个型号，逐行对完要二十分钟，
而且做到第 25 行时注意力已经不在了。这个工具做的就是这二十分钟里最机械的那部分：
**把所有对不上的地方摆到你面前，并告诉你它是从哪个格子读来的。**

关键设计取向：**宁可少报，也不错报。** 遇到读不懂的内容，它会明确说
「这里我读不准，请你看一眼」，而不是猜一个值。

## 2. 它明确不解决什么问题

这一节请完整读完。它比第 1 节更重要。

- **它不判断哪份文件是对的。** 它只告诉你「PO 写 1200，PI 写 1000」，
  不会说「应该以 PO 为准」。哪份对是商务判断，取决于你和客户最后谈成了什么。
- **它不批准订单、不修改单据、不发邮件。** 它只读文件，从不写回你的 Excel。
- **它不提供贸易合规、法律或财务意见。** 不判 HS 编码、不审信用证、不做出口管制筛查。
- **它不能替代人工复核。** 它可能漏掉差异（读不出某一列就不会比较那一列），
  也可能报出并非问题的差异（比如两份单据的编号本来就不一样）。
  **报告出来是零差异，不等于这单没问题**——只等于「在本工具能读到的范围内没发现不一致」。
- **缺席的文件 = 没检查，不等于一致。** 只上传两份时，第三份角色完全不参与比较，
  不会为它产生任何提示。界面和报告都会显示这条横幅提醒你。
- **它不接 ERP / CRM / 邮箱 / 微信 / WhatsApp**，不做订单管理，不做多用户和权限。

想要上面这些能力？先看 [`docs/future-scope.md`](docs/future-scope.md)，
那里记录了所有被推迟的需求以及推迟的理由。

## 3. 10 秒功能示意

假设你手上有两份文件：客户 PO 和你开的 PI。

**客户 PO（`po.xlsx`）**

| Item No. | Description | Qty | Unit | Unit Price | Amount |
|---|---|---|---|---|---|
| AB-100 | Ceramic Mug 350ml | 1000 | PCS | 1.25 | 1250.00 |
| AB-200 | Ceramic Plate 8in | 500 | PCS | **2.40** | 1200.00 |
| **AB-300** | Glass Bowl 500ml | 200 | PCS | 3.10 | 620.00 |

贸易术语 `FOB Ningbo`，总金额 `3070.00`

**你开的 PI（`pi.xlsx`）**

| Item No. | Description | Qty | Unit | Unit Price | Amount |
|---|---|---|---|---|---|
| AB-100 | Ceramic Mug 350ml | 1000 | PCS | 1.25 | 1250.00 |
| AB-200 | Ceramic Plate 8in | 500 | PCS | **2.50** | 1200.00 |

贸易术语 `CIF Ningbo`，总金额 `2450.00`

**工具的输出（以下是真实运行结果，不是示意稿）：**

| 风险 | 类型 | 位置 | 差异内容 |
|---|---|---|---|
| ▲ 严重 | 金额计算不符 | PI · AB-200 | 500 × 2.50 应为 **1250.00**，表上写的是 **1200.00** |
| ▲ 严重 | 取值冲突 | AB-200 · 单价 | PO = 2.40 ／ PI = **2.50** |
| ▲ 严重 | 取值冲突 | 总金额 | PO = 3070.00 ／ PI = **2450.00** |
| ▲ 严重 | 取值冲突 | 贸易术语 | PO = FOB ／ PI = **CIF** |
| ▲ 严重 | 行项目未对齐 | AB-300 | PO 里有，**PI 里没有** |
| ■ 待复核 | 取值冲突 | 单据日期 | PO = 2026-07-15 ／ PI = 2026-07-18 |
| ● 提示 | 取值冲突 | 单据号 | PO-8899 ／ PI-2026-001 |

注意最后两行：**单据日期不同、单据号不同是正常的**，所以它们不是「严重」。
风险等级按**发生在贸易链条的哪一段**来判：

- **报价单 → 客户 PO**：客户砍价、改数量是正常谈判，多数标为「提示」
- **客户 PO → PI**：这是卖方确认环节，**这里出错直接产生损失**，所以标为「严重」

如果所有字段一律标红，真正致命的那条就被淹没了。这是本项目最核心的一条设计决定。

每一条差异都可以展开看到证据：来自哪份文件、哪个工作表、哪个单元格、原文是什么。
比如上面那条计算错误，证据指向 PI 文件 `PROFORMA INVOICE` 工作表的
`C14`（数量）、`E14`（单价）、`F14`（金额）三个格子。

风险等级同时用**文字标签**和**形状记号**（▲ ◆ ■ ●）区分，不只靠颜色——
把报告打印成黑白或有色觉障碍时依然可读。

## 4. 支持的文件类型

**只支持 `.xlsx`。**

| 格式 | 支持 | 说明 |
|---|---|---|
| `.xlsx` | ✅ | Excel 2007 及以后的标准格式 |
| `.xls` | ❌ 明确拒绝 | 老式二进制格式 |
| `.xlsm` | ❌ 明确拒绝 | 含宏，本工具不执行任何宏 |
| `.pdf` | ❌ 明确拒绝 | **MVP-0 不支持 PDF**，计划在下一版本提供 |
| 扫描件 / 拍照 / 截图 | ❌ 明确拒绝 | 不做 OCR，不做图片识别 |
| `.doc` / `.docx` | ❌ 明确拒绝 | 不在范围内 |
| 加密 / 带密码的 Excel | ❌ 明确拒绝 | 无法读取，会提示「文件已加密」 |

「明确拒绝」的意思是：它会告诉你**为什么**不能处理这个文件，而不是假装成功后交给你
一张空报告。上传 PDF 会得到中文提示「MVP-0 暂不支持 PDF，将在下一版本提供」。

对 `.xlsx` 文件本身还有几条限制：

- 单个上传文件不超过 20MB
- 单个工作簿最多 20 个工作表
- 单个工作表最多 5000 行，全部工作表合计最多 20000 行
- 解压后体积超过 300MB 或压缩比异常的文件会被拒绝（防止恶意构造的文件撑爆内存）
- **单元格里的公式如果没有缓存值**（比如文件是程序生成、从没用 Excel 打开保存过），
  那些格子读不到数字，工具会提示你「请用 Excel 打开另存后重试」

## 5. 你的表格要长成什么样才能被读懂

工具**不要求**你改模板，但它需要在表里找到一张行项目表格。判定条件是：

**某一行里同时出现「数量类」表头和「单价或金额类」表头**，才会被认成表头行。

它认识的表头写法（大小写、全角半角、`(USD)` 这类括号后缀都会自动忽略）：

| 列的含义 | 认识的写法（部分） |
|---|---|
| 型号 | `Item No.`、`Model`、`SKU`、`Art. No`、`型号`、`货号`、`产品编号` |
| 品名 | `Description`、`Product Name`、`品名`、`产品名称` |
| 数量 | `Qty`、`Q'ty`、`Quantity`、`数量`、`订单数量` |
| 单位 | `Unit`、`UOM`、`单位` |
| 单价 | `Unit Price`、`U/P`、`单价` |
| 金额 | `Amount`、`Total Price`、`金额`、`小计` |
| 装箱数量 | `PCS/CTN`、`Qty/CTN`、`装箱数量`、`每箱数量` |
| 箱数 | `CTNS`、`Cartons`、`箱数` |

完整列表见 [`docs/comparison-rules.md`](docs/comparison-rules.md)（该文件由代码自动生成，
永远和实际行为一致）。

几条实际会遇到的情况：

- **公司抬头、合并的大标题、表格前的空行**：都能跳过，不影响识别
- **跨两行的表头**（上行 `Packing`，下行 `PCS/CTN`）：能识别
- **表格在第二个工作表**：能识别
- **表格中间有空行**：不影响，会继续往下读
- **表尾的「小计 / 运费 / 合计」行**：**不会**被当成产品行
- **一个表头同时像两个字段，或两列都像同一个字段**：两边都不映射，
  宁可少读一列，也不把 `Total Price` 认成单价

文档级信息（单据号、日期、买卖方、币种、贸易术语、付款条件、交期、总金额）
从表格外的「标签 : 值」区域读取，标签在左、值在右，或者标签在上、值在下。

**没有型号（SKU）的行不会和任何行匹配。** 这是刻意的：MVP-0 只做一级 SKU 精确匹配，
靠品名相似度猜对应关系属于下一版本。

## 6. 在 Windows 上安装并启动

以下命令全部在 **PowerShell** 里执行，**每一条都已实际验证**。

### 第 1 步：安装 Python 3.12

本项目需要 Python 3.12，**需要你自己安装**（系统不自带）。

```powershell
winget install --id Python.Python.3.12 --source winget
```

> **中国大陆用户必须加 `--source winget`。**
> 不加这个参数时 winget 会优先走 `msstore`（微软商店）源，在中国大陆经常长时间无响应
> 或直接失败。`--source winget` 走的是 python.org 的官方安装包，速度正常。

装完**关闭并重新打开 PowerShell**，然后验证：

```powershell
python -V
```

应该显示 `Python 3.12.10`（或其他 3.12.x 版本）。

> **如果这一步显示的是应用商店页面、或者版本不对**：
> Windows 自带一个叫「应用执行别名」的占位程序会抢占 `python` 这个名字。
> 打开「设置 → 应用 → 高级应用设置 → 应用执行别名」，把 `python.exe` 和 `python3.exe`
> 两项关掉，重新打开 PowerShell 再试。

### 第 2 步：建立独立的运行环境

```powershell
cd C:\Users\你的用户名\Documents\OrderDelta\backend
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

这会在 `backend\.venv\` 下建一个独立环境，把依赖装进去，**不污染你系统里的 Python**。

装完之后，**后面所有命令都用 `.venv\Scripts\python.exe`，不要直接用 `python`。**
这样即使你以后装了别的 Python 版本，这个项目也不受影响。

> 中国大陆网络下 pip 直连可能很慢，可以换成清华镜像：
> ```powershell
> .venv\Scripts\python.exe -m pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
> ```

### 第 3 步：后端自检

```powershell
.venv\Scripts\python.exe -m pytest -q
```

应该看到类似这样的结尾（**测试数量会随开发进度变化**，重要的是没有 `failed`）：

```
940 passed in 17.48s
```

全部通过 = 引擎在你这台机器上的行为和开发环境一致。

### 第 4 步：构建界面

需要先装 [Node.js](https://nodejs.org/)（LTS 版即可），然后：

```powershell
cd C:\Users\你的用户名\Documents\OrderDelta\frontend
npm ci
npm run build
```

> 中国大陆网络下 npm 直连可能很慢，可以换成镜像：
> ```powershell
> npm config set registry https://registry.npmmirror.com
> ```

构建产物会写到 `frontend\dist\`，由后端直接托管——**单端口、不需要额外起前端服务**。

### 第 5 步：启动

```powershell
cd C:\Users\你的用户名\Documents\OrderDelta\backend
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

看到 `Uvicorn running on http://127.0.0.1:8000` 之后，打开浏览器访问：

```
http://127.0.0.1:8000/projects
```

⚠️ **注意 `--host 127.0.0.1`：服务只监听本机，同一局域网里的其他电脑连不上。**
这是本版本唯一的访问控制手段（没有登录、没有密码）。
**不要把它改成 `0.0.0.0`**——那会让同一局域网内任何人无需密码打开你全部的订单数据。
详见 [`docs/security.md`](docs/security.md)。

停止服务：在那个 PowerShell 窗口里按 `Ctrl + C`。

> **给开发者**：如果你要改前端代码，可以在 `frontend\` 下另开一个窗口跑 `npm run dev`，
> 访问 `http://127.0.0.1:5173`，它会把 `/api` 请求代理到后端的 8000 端口。

## 7. 怎么用

1. 打开 `http://127.0.0.1:8000/projects`，**新建一个项目**（一个项目 = 一次核对任务）。
2. 进入项目页，看到三个上传槽位：**报价单（可选）、采购订单、形式发票**。
   至少上传**两份**才能运行检查。
3. 点**运行检查**。
4. 看差异列表：
   - 顶部的计数芯片（严重 / 警告 / 待复核 / 提示）**同时是筛选器**，点一下就只看那一类
   - 还可以按差异类型、型号、审核状态、文档角色筛选
   - 展开任意一条差异，看到**各份单据上的取值**以及**证据**（文件名 / 工作表 / 单元格 / 原文）
   - 每个取值都标明是「机器读取」还是「人工修正」
5. 逐条**审核**：确认差异 / 接受差异 / 忽略 / 已解决，可以写备注。
6. **导出 HTML 报告**，发给老板或客户。报告是单个文件，断网也能打开。
   报告会带上你做过的审核裁决与备注（**一条都没审核过时不显示这一列**，
   免得整列都是「待处理」白占版面）；依据已经变过的裁决会额外标注
   「本条裁决所依据的取值已变，请重新确认」。

### 关于重跑

如果你发现工具读错了某个值，可以提交一条**人工修正**，然后重新运行检查。这时：

- 你之前做过的审核判断**会被保留**
- 只有那些**判断依据发生了变化**的差异会被置为「待确认」，
  并且**保留你的备注**，同时告诉你「你上次是基于 PO 5000 / PI 4800 判断的」

这一条是刻意设计的：改一个值就把二十条审核标记清零，等于把你最花时间的工作抹掉。

## 8. 示例文件怎么用

仓库自带一个**示例文件生成器**，可以造出 16 组带已知差异的订单文件：

```powershell
cd C:\Users\你的用户名\Documents\OrderDelta\backend
.venv\Scripts\python.exe -m tools.fixtures.build
```

生成的文件在 `OrderDelta\fixtures\orders\<用例名>\` 下，每组包含
`quotation.xlsx` / `purchase_order.xlsx` / `proforma_invoice.xlsx`
（`two_docs_only` 那组刻意只有后两个——它就是用来验证「缺一份也能跑」的）。

只想看有哪些用例、不生成文件：

```powershell
.venv\Scripts\python.exe -m tools.fixtures.build --list
```

16 组用例分别是：

| 用例 | 造的是什么情况 |
|---|---|
| `identical` | 三份完全一致（**用来验证不误报**） |
| `po_quantity_changed` | 客户 PO 改了数量 |
| `pi_unit_price_wrong` | PI 单价错了 |
| `currency_mismatch` | 币种不一致 |
| `incoterm_mismatch` | 贸易术语不一致（FOB vs CIF） |
| `incoterm_place_mismatch` | 贸易术语地点不一致（FOB Shanghai vs FOB Ningbo） |
| `payment_terms_mismatch` | 付款比例不一致 |
| `po_extra_sku` | 客户 PO 上多了一个型号 |
| `pi_missing_sku` | PI 上漏了一个型号 |
| `row_order_shuffled` | 行顺序不同（**不应该产生差异**） |
| `duplicate_sku` | 同一型号出现多行（**应该标歧义，不该硬比**） |
| `line_total_wrong` | 行金额 / 总金额算错 |
| `two_docs_only` | 只有 PO + PI 两份 |
| `layout_merged_title` | 版面变体：公司抬头 + 合并大标题（语义同 `identical`，**换版面不该产生差异**） |
| `layout_chinese_headers` | 版面变体：纯中文标签与表头（语义同 `payment_terms_mismatch`） |
| `layout_second_sheet` | 版面变体：订单表在第二个 sheet（语义同 `pi_unit_price_wrong`） |

**推荐第一次这样试**：先上传 `identical` 那组的三个文件，跑一遍——应该看不到任何「严重」。
再上传 `pi_unit_price_wrong` 那组，对比一下差别。

> 生成器**不用随机数**，每一个字节都由代码里的参数决定，所以重复生成得到的文件
> **逐字节相同**。这是可复现验证的前提。

如果你想用自己的文件试，按第 5 节的表格要求准备两份 `.xlsx` 即可。

## 9. 需要模型 API 吗？需要联网吗？

**都不需要。**

- **MVP-0 不调用任何外部模型。** 没有 OpenAI、没有 Claude、没有国内任何大模型服务。
  整个比对过程是确定性规则运算：同样的两个文件，跑一百遍结果逐字节相同。
- **不需要任何 API Key。** 你不会在任何地方被要求填密钥。
  （可以自己验证：访问 `http://127.0.0.1:8000/api/v1/health`，返回里的
  `"llm_enabled"` 恒为 `false`——它是 `app/api/routes.py` 里写死的字面量，
  没有任何配置项能把它翻成 `true`。）
- **MVP-0 里根本没有模型适配器代码**：`backend/app/` 下 grep `llm` 只能命中注释，
  既没有 provider、没有客户端、也没有开关。所以这不是「默认关闭」，是「还没有」。
- 将来接入时的形状已经由 SPEC §14 定死（模型**只能从已解析出的文本块里「选」一个，
  不能「写」一个值**，凭空编造数字在结构上不可能发生），并且**必须靠显式配置开关启用**——
  「环境变量里恰好有个 key」不构成启用条件。详见
  [`docs/architecture.md`](docs/architecture.md) 的「LLM 边界」一节。

**联网只在三个时刻需要**：第一次安装 Python、第一次装后端依赖、第一次装前端依赖。
装完之后断网也能跑。

## 10. 我的文件会离开这台电脑吗？

**不会。**

- 没有云端服务，没有上传，没有遥测，没有崩溃上报，没有使用统计。
- 所有解析、比较、生成报告都在你自己的电脑上完成。
- 后端默认只监听 `127.0.0.1`（本机回环地址），
  **同一个局域网内的其他电脑也访问不到**。
- 生成的 HTML 报告是**自包含**的：不引用任何外部网址、不含任何脚本，
  断网、关掉后端也能用浏览器打开。这一条有机械检查强制
  （报告文件里出现任何 `http://` / `https://` 即判测试失败）。

唯一的例外是你自己主动做的事：把报告文件发给别人、把整个文件夹拷到网盘。
工具不阻止你这么做，但它自己不会做。

## 11. 数据保存在哪里

全部在仓库目录下的 `data\` 文件夹里：

| 内容 | 位置 |
|---|---|
| 数据库（项目、文档记录、差异、审核状态、人工修正） | `OrderDelta\data\orderdelta.sqlite3` |
| 你上传的原始 Excel | `OrderDelta\data\files\` |

两点说明：

- **原始文件名只作为元数据保存在数据库里**，磁盘上用随机字符串命名
  （例如 `3f9a2c...e1.xlsx`）。这样即使有人上传一个名字里带路径符号的恶意文件，
  也不会影响你电脑上的其他文件。
- `data\` 目录已经被 `.gitignore` 排除，**不会被提交到版本库**——
  你的客户订单内容不会因为一次 `git push` 泄漏出去。

想换个位置存？复制 `.env.example` 为 `.env`，取消 `ORDERDELTA_DATA_DIR` 那一行的注释并改掉。

## 12. 怎么删除数据

**删除单个项目**：在项目列表里点删除。这会**删除该项目在数据库里的记录，
并删除磁盘上对应的原始 Excel 文件**。

**清空全部**：先停掉服务（`Ctrl + C`），然后直接删掉 `OrderDelta\data\` 整个目录。
下次启动会重新建一个空的。

关于删除，有一件事必须说清楚：

> 本工具执行的是**删除数据库记录与磁盘上的原始文件**。
> 在 SQLite + 普通文件系统 + SSD 的组合下，**做不到把数据从物理介质上彻底清除**
> （写时复制、磨损均衡、系统还原点都可能留下副本）。
> 对于确实敏感的数据，请依靠整盘加密（BitLocker）等系统级手段，
> 而不是依靠本工具的删除功能。

这是本项目刻意规定的措辞。任何宣称「安全擦除」的说法都是不诚实的。

**另外：导出的 HTML 报告不在工具的管理范围内。** 它是你自己保存的普通文件，
含有完整订单数据，删除它是你自己的事。

## 13. 怎么跑测试

后端（在 `backend` 目录下）：

```powershell
.venv\Scripts\python.exe -m pytest -q                              # 跑全部测试
.venv\Scripts\python.exe -m pytest -v                              # 显示每个测试的名字
.venv\Scripts\python.exe -m pytest tests\test_pipeline_e2e.py -v   # 只跑端到端测试
.venv\Scripts\python.exe -m pytest -m golden                       # 只跑 16 组示例用例
```

测试的名字是**中文的业务规则描述**，非程序员也能看懂在验证什么，例如：

```
test_critical误报为零
test_报价单多出的sku只是info
test_缺席角色不产生任何差异
test_pi内部算术错误被抓到
test_修正后重跑保留未受影响的裁决
test_文件内无任何外部http引用
```

前端（在 `frontend` 目录下）：

```powershell
npm test          # 单元测试
npm run lint      # 代码风格
npm run typecheck # 类型检查
```

**一次跑完全部并生成证据报告**（需要 Git Bash，随 Git for Windows 一起安装）：

```powershell
cd C:\Users\你的用户名\Documents\OrderDelta
.\scripts\verify.ps1
```

它会把每一条命令、完整输出和退出码写进 `docs\validation-report.md`。
**失败不中断**——跑完全部再汇总，让你看到全貌而不是第一个红灯。

给开发者的其他检查命令（在 `backend` 下）：

```powershell
.venv\Scripts\python.exe -m ruff check .              # 代码风格
.venv\Scripts\python.exe -m ruff format --check .     # 格式化检查（不改文件）
.venv\Scripts\python.exe -m mypy app                  # 类型检查
.venv\Scripts\python.exe -m tools.gen_docs --check    # 校验 comparison-rules.md 与代码同步
.venv\Scripts\python.exe -m tools.mvp1_report         # 本轮实际执行 / MVP-1 反选数 / 仓库内总数
```

最后一条解释 `pytest -q` 那个「N passed」是怎么来的：`pyproject.toml` 的
`addopts` 里挂了 `-m 'not mvp1'`，所以它是**反选之后**的数字。
`tools.mvp1_report` 把三个数一起打印出来，三个数对不上就失败——
「悄悄摘掉一批测试」这条路被堵死。`scripts/verify.sh` 会在跑完全部测试之后自动调它。

## 14. 当前的准确性限制（请务必读完）

这一节说的是**已知会读错或读不到的情况**。不要在没读完这一节的情况下把它用在真实订单上。

1. **准确率未知，且不得对外宣称。** 现有测试全部使用程序化构造的 Excel 文件，
   这些文件和提取器共用同一套表头假设。测试全绿只证明**引擎逻辑自洽且稳定**，
   **不代表它能读懂你客户发来的真实单据**。真实准确率在接入真实语料验证前是未知数。
   完整免责声明见 [`docs/limitations.md`](docs/limitations.md)。
2. **读不出的列不会被比较，也不会有提示。** 如果你的表头写法不在别名表里（比如写成 `Nos.`），
   那一列就不会被识别，对应字段的差异**不会被发现**。
   **这是本工具最主要的漏报来源**，而且当前界面还没有把「有一列我没读懂」显示出来。
3. **只做型号（SKU）精确匹配。** 没有型号的行不参与匹配。型号写法不同
   （`AB-100` vs `AB100`）默认视为**两个不同的型号**。
4. **不做任何单位换算。** `SETS` 和 `PCS`、`CTNS` 和 `PCS` 之间不换算，
   遇到单位不同会标为「无法比较」交给你判断。
5. **同一个型号在一份文件里出现多行**（比如按颜色拆行）时，工具**只标记「存在歧义，
   需人工确认」，不做求和，也不做拆合推断**。因为求和后再比较等于替你裁定
   「分批交货 = 整批交货」，这不是工具该做的判断。
6. **总金额和行金额之和对不上时不判为错误**，而是标为「存在未解释差额 X」——
   真实 PI 上几乎总有运费、折扣、模具费。
7. **日期歧义不猜。** `08/09/2026` 到底是 8 月 9 日还是 9 月 8 日，工具不擅自决定，
   标为待确认。
8. **单独的 `$` 符号不认定为美元**（可能是港币、澳元、新元），标为待确认。
9. **没有身份认证、单机单用户。** 详见 [`docs/security.md`](docs/security.md)。
10. **有一项已知的性能风险**：解析超时限制**尚未实现**，一份构造得当的大文件可能让一次
    上传长时间占用后端。已有文件大小、行数、工作表数等多重上限做间接缓解。
    详见 [`docs/security.md`](docs/security.md) §4.2。

一句话总结：**这个工具会告诉你它发现了什么，但它发现不了的东西，它自己也不知道。
最终复核责任在你。**

## 16. 企业适配可能涉及什么

如果你想把它用在公司实际业务里，下面这些事情大概率需要处理。
**这不是承诺路线图，是一份诚实的成本清单。**

**必须先做的（否则不建议接触真实订单）**

- **用你公司的真实单据做验证**：拿 30–50 份真实的历史 PO/PI 跑一遍，人工核对结果，
  统计漏报和误报。**这是唯一能得出真实准确率的办法**，现有测试做不到这件事。
- **扩充表头别名表**：你公司和主要客户的模板里那些特殊写法，需要加进别名表
  （`backend\app\domain\fields.py`）。这是修改一个列表，不需要改逻辑。
- **补上解析超时**：见第 14 节第 10 条。

**很可能需要的**

- **PDF 支持**：客户发来的 PI 常常是 PDF。这是下一版本的主要内容，接口形状已经预留，
  但实现工作量不小（还要处理扫描件和中文字体缺 ToUnicode 的情况）。
- **客户料号映射**：客户 PO 上写的是他们自己的料号，需要一张映射表把它对到你的内部型号。
- **风险等级调整**：默认的严重度表（哪些字段在哪个环节算严重）来自通用外贸场景。
  你公司可能有不同判断——比如包装数量对某些行业就是致命的。这是改配置表，不改逻辑。
- **单位换算规则**：如果你公司有明确的 `1 SET = 4 PCS` 之类的换算规则，可以补进去。
  工具默认拒绝换算，是因为在没有企业规则的前提下换算等于瞎猜。
- **Excel 导出**：目前只有 HTML 报告。做 Excel 导出时**必须处理公式注入**——
  客户单据里 `=D5*E5` 这种写法极常见，直接写进导出文件会被 Excel 按新表格重新求值，
  在「引用原文」的位置静默显示一个错数字。
- **数据库迁移方案**：当前直接建表，**schema 改动没有升级路径**，
  升级版本时旧数据可能需要手工处理。

**如果要多人一起用**

当前设计是**单机单用户、无登录**，靠「只监听本机」来保证别人访问不到。
要变成多人共用，需要新增：身份认证、权限体系、审计日志、HTTPS、多租户数据隔离。
**这些都不是加个开关能解决的**，属于一次实质的架构扩展。

⚠️ **请不要用「把绑定地址改成 `0.0.0.0`」的方式来实现多人共用。**
那样做的效果是：同一个局域网内的任何人，无需任何密码就能打开、导出、删除你全部的订单数据。
如果确实需要局域网访问，正确做法是在前面加一层**带认证的反向代理**。
